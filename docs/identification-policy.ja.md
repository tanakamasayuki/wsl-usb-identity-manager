# 識別ポリシー（設計方針）

作成日: 2026-09-02
前提: [docs/research-findings.ja.md](research-findings.ja.md)

---

## 1. 出発点

調査 F3 で確定した事実。

> Windows が提供する情報だけでは、シリアルを持たない CH340 が複数ある場合、
> 「どのポートに刺さっているか」以上のことは分からない。

したがって個体識別にはプローブ（対象への問い合わせ）が要る。
しかし調査 F8 の通り、プローブには副作用がある。

- `esptool` 系は DTR/RTS を操作するため **ファームウェアが再起動する**
- WCH-Link の attach は **ターゲットのコアを一時停止させる**
- プローブ中のシリアル出力は失われる

**したがって「識別のためにプローブする」と「プローブしてはいけない」が正面から衝突する。**
本アプリの設計の中心は、この衝突をどう捌くかにある。

---

## 2. 基本方針

> **プローブは「いつでも安全ではない」が「安全な瞬間はある」。
> その瞬間を狙い、それ以外はキャッシュで済ませる。**

安全な瞬間は 2 つある。

1. **ユーザーが明示的に指示したとき** — 副作用を承知の上での操作
2. **デバイスが接続された直後** — まだ誰も使い始めていないため、リセットされても実害が少ない

この 2 つ以外では、**プローブを一切行わない。**

---

## 3. 識別の 3 経路

### 経路 1: USB シリアルによる識別（プローブ不要）

デバイスが USB シリアル番号を持つ場合、Instance ID の第 3 要素がそのまま個体識別子になる。

```text
USB\VID_1A86&PID_55D3\5B5F090816            CH343
USB\VID_303A&PID_1001\70:04:1D:DA:86:F0     ESP32-S3 native USB（MAC がシリアル）
USB\VID_2341&PID_0043\8573531333335160D1C2  Arduino Uno
```

この場合、**前回の識別結果をキャッシュから復元するだけでよく、プローブは一切不要**。
ポートを差し替えても、再起動しても、同じシリアルなら同じデバイスである。

ESP32-S3 / C3 などのネイティブ USB 機種は MAC アドレスがシリアルになるため、
**この経路だけで完全に識別できる**（プローブが必要なのは CH340 等を介した旧 ESP32 のみ）。

→ **シリアルを持つデバイスは、原則としてプローブしない。**

### 経路 2: キャッシュ照合（プローブ不要）

シリアルを持たないデバイスは、以下のヒントを組み合わせて登録済みデバイスと照合する。

- `LocationPaths`（物理ポート、F2）
- VID / PID
- 直前の切断からの経過時間
- 同一 VID/PID の他候補が同時に存在するか

候補が一意に定まれば、**プローブせずに登録済みの Identity を復元する。**

### 経路 3: プローブによる識別（副作用あり）

経路 1・2 で決まらないときのみ。実行契機は §2 の 2 つに限る。

---

## 4. 確信度モデル

各デバイスは常に「確信度」を持ち、UI と自動処理の判断材料になる。

| confidence | 根拠 | プローブ | 自動 Attach |
| --- | --- | --- | --- |
| `confirmed` | Application Identity 一致、または USB シリアル一致 | 不要 | 可 |
| `probable` | ポート位置 + VID/PID が登録と一致し、競合候補なし | 不要 | 設定次第 |
| `ambiguous` | 同一 VID/PID の候補が複数 / 位置が変わった | 要（ユーザー操作） | **不可** |
| `unknown` | 未登録 | 要（ユーザー操作） | 不可 |

UI 上でも確信度を明示する。
「たぶんこれ」を「これ」と偽らないことが、この設計の要点である。

## 5. プローブの実行契機

### 5.1 明示的プローブ（既定で有効）

デバイス一覧および詳細画面の **「識別」ボタン**。

- 押した瞬間にプローブを実行する
- 副作用（ボードが再起動する等）を実行前に明示する
- `ambiguous` / `unknown` のデバイスでは、ボタンを目立たせる

### 5.2 接続直後の自動識別（オプション、既定で無効）

USB 接続イベントから一定時間内に限り、自動でプローブしてよいとする設定。

**根拠**: 挿した直後のボードはまだ使われていないことが多く、
リセットされても実害が出にくい。

設定項目（案）:

| 項目 | 既定値 | 説明 |
| --- | --- | --- |
| 自動識別 | 無効 | 機能全体の ON/OFF |
| 対象 | シリアルを持たないデバイスのみ | シリアル持ちは経路 1 で足りるため対象外 |
| 猶予時間 | 接続イベントから 10 秒以内 | これを過ぎたら自動実行しない |
| 対象 VID/PID | ユーザーが列挙 | 未知のデバイスに無条件送信しない（memo 4.2） |
| 確信度の下限 | `ambiguous` 以下のみ | すでに確定しているものは触らない |

**この機能を既定で無効にする理由**: 副作用のある動作を、
ユーザーが明示的に許可していない状態で走らせるべきではないため。

### 5.3 プローブを行わない場面（禁止事項）

- 定期ポーリング
- 一覧画面の更新
- アプリ起動時の一括スキャン
- 自動 Attach の判定のため

## 6. キャッシュの構造

```text
Identity（永続）
  identity_key        確定した識別子（board-identify 互換形式）
                        例: esp32-s3-7cdfa1123456
  usb_serial          あれば。経路 1 の照合キー
  vid / pid
  application_identity  プローブで得た情報（Device ID / Type / Rev / FW）
  user_metadata       Alias / Memo / Tags / Default WSL / Auto Attach

Hints（学習・更新される）
  last_location_path  最後に見た物理ポート（F2）
  last_instance_id    最後に見た Instance ID（usbipd との結合キー、F4）
  last_com_port       参考表示用（永続的な識別には使わない）
  last_seen_at
  probe_result_at     最後にプローブした日時
```

**永続化してはならないもの**（調査 F1 より）:

- BUSID
- COM 番号を識別子として（表示用の参考値としては保持してよい）
- `/dev/ttyUSB*` などの Linux デバイスノード

## 7. 具体的なシナリオ

### CH340 が 3 個、それぞれ別のボードに繋がっている

**初回登録**

1. 3 個とも `unknown` として一覧に出る（`VID_1A86&PID_7523`、ポートのみ相違）
2. ユーザーが 1 個ずつ「識別」を押す
3. プローブが走り、それぞれ `esp32-7cdfa1123456` 等が確定する
4. ユーザーが Alias（「会議室 CO2 センサー」等）を付ける
5. ポート位置がヒントとして記録される

**2 回目以降（同じポートに挿す）**

1. 接続イベント → ポート位置 + VID/PID で照合 → 一意に定まる
2. `probable` として Alias を表示。**プローブは走らない**
3. 自動 Attach 設定があればそのまま Attach

**ポートを入れ替えた場合**

1. 照合結果が競合 → 3 個とも `ambiguous`
2. Alias は出すが「未確認」を明示し、**自動 Attach は行わない**
3. ユーザーが「識別」を押せば確定し、ヒントが更新される

### ESP32-S3（ネイティブ USB）

シリアル（MAC）を持つため、初回から `confirmed`。**一度もプローブしない。**
