## 0.2.0 - 2026-09-16

- (EN) Add automatic attach. A rule names a device by its board ID, its USB serial number, its VID:PID or its bus id, and a matching device is handed to WSL as soon as usbipd is sharing it and Windows can see it. Ordered most specific first, so a device covered by both its board ID and its VID:PID reports the board ID. Deciding a rule never probes (R9.4): a board-ID rule simply waits until the board has been identified, and a device queued for identification is not attached until that has run, since attaching it first would take away the only chance to ask. Automatic attach is attempted once per plug-in, so a failure does not repeat every two seconds and a manual detach is not immediately undone. Nothing is ever shared automatically — that needs administrator rights, and an automatic action must not raise a UAC prompt. The master switch sits in the toolbar rather than in a dialog, rules are listed and edited in their own panel with a live count of what each one matches, and the detail pane offers the selected device's own values as an exclusive radio group. Removing a rule from there that also covered other devices says so.
- (JA) 自動 Attach を追加。条件はボード ID / USB シリアル / VID:PID / BUSID のいずれかでデバイスを指定し、一致したデバイスは usbipd で共有済みかつ Windows から見えている時点で WSL に接続される。具体的な種類が優先されるため、ボード ID と VID:PID の両方に一致するデバイスはボード ID で一致したと報告する。条件の判定はプローブを行わない(R9.4)。ボード ID の条件は識別されるまで待つだけであり、識別待ちのデバイスは識別が終わるまで Attach しない(先に Attach すると問い合わせる機会そのものが失われるため)。自動 Attach は接続ごとに 1 度だけ試行するので、失敗が 2 秒ごとに繰り返されることも、手動の Detach が即座に取り消されることもない。自動で共有(bind)することは一切しない。管理者権限が必要であり、自動処理が UAC を出すべきではないため。有効/無効の切り替えはダイアログではなくツールバーに置き、条件の一覧・追加・削除は専用画面で現在の一致台数とともに行う。詳細画面では、選択したデバイスが持つ値をラジオボタンで排他的に選べる。そこで削除された条件が他のデバイスにも一致していた場合はその旨を表示する。
- (EN) Refuse to start a second copy. A named mutex, scoped to the sign-in session, decides; the second copy raises the running window and exits. Two copies would poll usbipd together and act on the same automatic rules, racing each other to attach one device.
- (JA) 多重起動を禁止。サインインセッション単位の名前付きミューテックスで判定し、2 つ目はすでに動いているウィンドウを前面に出して終了する。2 つ動いていれば両方が usbipd を叩き、同じ自動 Attach の条件を実行して同じデバイスの取り合いになる。
- (EN) Fix "stop sharing" on a device that is not connected. The button was offered and then failed, because the bind record outlives the device and every operation was issued by bus id — which an absent device does not have. usbipd names a record with no device behind it by its persisted GUID, and unbind now uses that. The GUID is read from `usbipd state` immediately before the command and validated before it reaches an elevated command line, exactly as the bus id is.
- (JA) 未接続のデバイスに対する「共有をやめる」がエラーになる問題を修正。共有の記録はデバイスが無くなっても残るのにすべての操作を BUSID で発行していたため、BUSID を持たない未接続デバイスで失敗していた。usbipd は記録のみのデバイスを `PersistedGuid` で指定できるので、Unbind ではそちらを使う。GUID はコマンド発行の直前に `usbipd state` から読み、昇格実行のコマンドラインに載せる前に形式を検査する(BUSID と同じ扱い)。
- (EN) Rename the Transport and Target columns to "USB serial number" and "Board". Those are the names of layers in the design model, not words a user brings with them; the cells hold a USB serial number and a board identifier, and saying so removes the need to explain. "Number" is part of it because nearly everything this application deals with sits behind a USB-serial adapter, where "serial" on its own reads as the serial line. The layer distinction stays in the tooltips and the detail pane.
- (JA) Transport / Target の列見出しを「USB シリアル番号」「ボード」に変更。これらは設計モデル上の層の名前であって利用者の語彙ではない。セルに入っているのは USB のシリアル番号とボードの識別子であり、そう書けば説明が要らない。「番号」まで書くのは、扱う対象がほぼ全て USB シリアル変換であり「シリアル」だけではシリアル回線と読めるため。層の区別はツールチップと詳細画面が引き続き担う。
- (EN) Refresh the device list after a failed usbipd operation. The list was only handed back on success, so a failed attach left the state from before the attempt on screen next to an error saying it had not happened — which reads as if it had. A failure says nothing about how far usbipd got, so the answer is to ask it again rather than to assume either way.
- (JA) usbipd の操作が失敗したときも一覧を取得し直すようにした。成功時にしか新しい一覧を返していなかったため、Attach に失敗すると「失敗した」というエラーの隣に操作前の状態が残り、成功したように読めていた。失敗は「何も起きなかった」を意味しないので、決めつけずに取得し直す。
- (EN) Move the auto-attach marker out of the state cell into its own column. Beside the state it pushed "WSL 接続中" out of a column sized for it. The column also shows a match while automatic attach is switched off, greyed and saying so, because rules are usually built before the switch is turned on and there is no way to aim them without seeing what they currently hit.
- (JA) 自動 Attach のマーカーを状態列から独立した「自動」列へ移動。状態列に並べると「WSL 接続中」がはみ出していた。自動 Attach が OFF のときも一致を表示し(グレー表示とツールチップで実行されないことを示す)、条件を組み立てている最中に何に一致しているかが見えるようにした。
- (EN) Stop the detail pane describing a device the current tab does not list. The selection is now found among the rows on screen, so switching tabs leaves nothing selected rather than leaving a pane full of a device with no highlighted row — and going back to the tab the device is in brings the selection back.
- (JA) タブを切り替えたときに、そのタブに無いデバイスの内容が詳細画面に残り続ける問題を修正。選択は画面に出ている行の中から探すようにしたので、タブを移ると選択なしになる(行がハイライトされていないのに詳細だけ残る状態を無くした)。元のタブに戻れば選択も戻る。

- (EN) Reorganise the documentation so it describes the specification as it stands, with no project-status framing. Removes the milestone section, the first-release scope split and the open-question markers; the identification policy is rewritten around the decision not to persist identification results, replacing the cache-matching routes and the confidence model with a stated lifetime (an identity lasts exactly as long as the device stays plugged in) and with probe precedence (a probe that recognises hardware by VID/PID suppresses the fallback probes). Records the measurement that corrects finding F6: a WCH-Link's vendor interface is bound to WCH's own `WCHLink_A64` driver, and `ch32rv-usb` falls back to that driver when nusb cannot claim the interface, so requirement R4.12 now forbids asking the user to replace it with WinUSB instead of requiring WinUSB. Also records that `set_speed` failure must not fail an identification (the CH549-based WCH-Link firmware 2.6 does not implement it), that arrival is detected from device-node reachability rather than the bus id usbipd keeps reporting through an attach, and that a value must be validated before it is placed on an elevated command line.
- (JA) ドキュメントを、現在の仕様そのものを記す形に整理。マイルストーン、初期リリース範囲、未決定の印を削除。識別ポリシーは「識別結果を永続化しない」という決定を軸に書き直し、キャッシュ照合の経路と確信度モデルを、識別結果の寿命(接続されている間だけ)とプローブの優先順位(VID/PID で特定できるプローブがフォールバックを抑止する)に置き換えた。調査 F6 を訂正する実測を記録: WCH-Link のベンダインタフェースには WCH 純正の `WCHLink_A64` が当たっており、`ch32rv-usb` は nusb で claim できない場合にその純正ドライバ経路へフォールバックする。よって要件 R4.12 は「WinUSB を要求する」から「WinUSB への差し替えを求めてはならない」に反転した。あわせて `set_speed` の失敗を識別の失敗としてはならないこと(CH549 ベースの WCH-Link firmware 2.6 は未実装)、接続の検出には Attach 中も残る BUSID ではなくデバイスノードへの到達性を用いること、昇格実行のコマンドラインへ埋め込む値を事前に検査することを記録。

## 0.1.2 - 2026-09-15

- (EN) Add the requirements specification (`docs/requirements.ja.md`). States the goal as identifying the **target** board behind an adapter or debug probe, not merely the adapter itself: a CH340's serial number belongs to the adapter and a WCH-LinkE's to the probe, neither of which changes when the board behind it is swapped. Adopts the three-layer model (Port / Transport / Target) and requires the UI to distinguish which layer an identifier came from. Target identification is limited to two families for now — ESP32 via the eFuse MAC and CH32 RISC-V via the part UUID — with everything else identified down to the transport only and reported as such. Also defines the four-part state model, the three identification paths with a per-device confidence level, the two moments at which probing is permitted, `usbipd` integration keyed on `InstanceId` rather than the bus ID, the data model and what must never be persisted, UI requirements including language auto-detection with a manual override, the technical stack, and the distribution and release process. Scope for the first release is listed separately from the follow-up work.
- (JA) 要件定義書(`docs/requirements.ja.md`)を追加。目的を「アダプタやデバッグプローブ自体ではなく、その先の **Target** ボードまで識別すること」と明記。CH340 のシリアル番号はアダプタのもの、WCH-LinkE のシリアル番号はプローブのものであり、いずれも先のボードを載せ替えても変わらない。3 層モデル(Port / Transport / Target)を採用し、表示中の識別子がどの層のものかを UI で区別することを要件化。Target まで識別できるのは当面 2 系統(eFuse MAC による ESP32 系、部品 UUID による CH32 RISC-V 系)のみとし、それ以外は Transport までの識別に留めてその旨を明示する。あわせて 4 つの情報群による状態モデル、確信度を伴う 3 経路の識別方式、プローブを許可する 2 つの契機、BUSID ではなく `InstanceId` を結合キーとする `usbipd` 連携、データモデルと永続化禁止項目、表示言語の自動判定と手動選択を含む UI 要件、技術スタック、配布とリリース手順を定義。初期リリース範囲と後続の拡張を分けて記載。
- (EN) Add the research findings (`docs/research-findings.ja.md`) from measurements on a live machine. Establishes that a `usbipd` bus ID is `Hub_#NNNN` plus `Port_#MMMM` where the hub number is assigned in Windows enumeration order and therefore cannot be persisted; that `ContainerId` is a deterministic UUIDv5 for devices with a serial number but a per-port UUIDv1 for devices without one, so it degenerates into a port identifier for a CH340; that a WCH-Link vendor interface is reachable from an ordinary unelevated Windows application when WinUSB is bound; and that enumerating USB devices through the PowerShell PnP cmdlets is over 700 times slower than calling `CfgMgr32` directly.
- (JA) 実機実測にもとづく事前調査結果(`docs/research-findings.ja.md`)を追加。`usbipd` の BUSID が `Hub_#NNNN` と `Port_#MMMM` の組であり、ハブ番号は Windows の列挙順に振られるため永続化できないこと、`ContainerId` がシリアル有りでは決定論的な UUIDv5、シリアル無しではポート単位の UUIDv1 となり CH340 ではポート識別子に退化すること、WinUSB がバインドされていれば WCH-Link のベンダインタフェースに非昇格の通常アプリからアクセスできること、PowerShell の PnP コマンドレット経由の USB 列挙が `CfgMgr32` 直接呼び出しより 700 倍以上遅いことを確認。
- (EN) Confirm the ch32rv dependency against the crates.io release. `ch32rv-wchlink`, `ch32rv-usb`, `ch32rv-target` and their dependencies are published at 0.2.0, and the identification path is verified present: `WchLink::open` → `probe_info` → `set_speed_default` → `attach_chip` → `chip_info` → `detach_chip`, where `ChipInfo.uuid` is an 8-byte factory UUID that serves as the per-board identifier and `AttachInfo` carries the family and chip id for SKU resolution. Since ch32rv is pre-1.0, the dependency is pinned to `"0.2"` and a minor bump may not be taken without re-verifying identification on real hardware. Record that `ch32rv-usb` enumeration is used only to locate and open the probe, never as the application's device inventory, and that a WCH-Link in ARM mode must be reported rather than switched automatically.
- (JA) ch32rv への依存を crates.io 公開版で確認。`ch32rv-wchlink` / `ch32rv-usb` / `ch32rv-target` とその依存が 0.2.0 で公開済みであり、識別経路の存在を確認した(`WchLink::open` → `probe_info` → `set_speed_default` → `attach_chip` → `chip_info` → `detach_chip`)。`ChipInfo.uuid` が 8 バイトの工場出荷時 UUID でボード個体識別子となり、`AttachInfo` が SKU 解決用の family と chip id を持つ。ch32rv は 1.0 到達前のため依存を `"0.2"` に固定し、マイナー版の引き上げは実機での識別動作を再確認するまで行わない。`ch32rv-usb` の列挙はプローブの発見とオープンにのみ用い本アプリのデバイス一覧の情報源とはしないこと、ARM モードの WCH-Link は自動切り替えせず案内に留めることを明記。
- (EN) Drop the milestone blocker on ch32rv now that it is published. M1 and M2 stay separate as a delivery-order decision — isolating pre-1.0 API churn, keeping the WinUSB-driver and RISC-V-mode UX out of the first release, and narrowing what the resolution algorithm is tuned against — rather than as a dependency constraint.
- (JA) ch32rv の公開によりマイルストーンのブロッカーを解消。M1 と M2 の分割は依存制約ではなく納品順序の判断として維持する(1.0 前の API 変動を M1 に波及させない、WinUSB ドライバ割り当てと RISC-V モードの UX を初版から外す、判定アルゴリズムの調整対象を絞る)。
- (EN) Specify the confidence resolution algorithm as a provisional design (`docs/identification-policy.ja.md` §5). Resolution operates on the set of devices sharing a VID/PID rather than on each device independently, because per-device matching reports both devices under the wrong name when two are swapped between ports. Serial numbers bind first and outrank port position; within a group, a device whose remembered port is unoccupied by anyone else resolves to `probable`, a device appearing at a port no record claims stays `unknown` without affecting its neighbours, and a device landing on another record's remembered port drops everything involved in that collision to `ambiguous`. A full swap between two ports is documented as undetectable in principle and is required to be kept as a regression test rather than silently fixed. The six parameters expected to change after hands-on use are listed, and the resolution is required to be a single side-effect-free function so tuning stays contained.
- (JA) 確信度の判定アルゴリズムを暫定仕様として規定(`docs/identification-policy.ja.md` §5)。デバイス個別ではなく VID/PID を共有する集合を単位に解決する(個別照合では 2 台をポート間で入れ替えたときに両方とも誤った名前で表示されるため)。シリアル番号が最優先で束縛されポート位置に優越する。グループ内では、記憶ポートが他の誰にも占有されていないデバイスは `probable`、どの記録も主張しないポートに現れたデバイスは隣接デバイスに影響を与えずに `unknown`、他の記録の記憶ポートに着地したデバイスはその衝突に関わる全員を `ambiguous` に落とす。2 ポート間の完全な入れ替えは原理的に検出不能であることを明記し、暗黙に壊さないよう回帰テストとして保持することを要件化。実機使用後に変更が想定される 6 つのパラメータを列挙し、調整が閉じるよう判定を副作用のない単一関数とすることを要件とした。
- (EN) Drop the requirement that identifiers match board-identify. The identifier is internal to this application; what is required instead is that generation be deterministic and stable across releases, since it is the key against persisted data.
- (JA) 識別子を board-identify と一致させる要件を削除。識別子は本アプリケーション内部のものとし、代わりに永続データの照合キーであることから、生成が決定論的でリリースをまたいで安定であることを要件とした。
- (EN) Split delivery into milestones: M1 ships with ESP32 target identification only, and M2 adds CH32 without touching M1's resolution logic, data model or UI. Adopt ch32rv's engineering standards (edition 2024, rust-version 1.88, `unsafe_code = "forbid"`, `unwrap`/`expect`/`panic` denied) with FFI isolated into its own crate.
- (JA) 提供をマイルストーンに分割。M1 は ESP32 系のみで出荷し、M2 は M1 の判定ロジック・データモデル・UI に手を入れずに CH32 を追加する。ch32rv の実装規律(edition 2024、rust-version 1.88、`unsafe_code = "forbid"`、`unwrap`/`expect`/`panic` を deny)を採用し、FFI は専用 crate に隔離する。
- (EN) Add diagnostics and error handling (`docs/requirements.ja.md` §13) and the settings schema (§7.4). Prerequisites are checked at startup and reported with a remedy rather than failing silently, and the application still runs with whatever subset is satisfied. Operation results are confirmed by re-reading `usbipd state` rather than trusting an exit code, a timeout reports "issued but unconfirmed" instead of guessing, concurrent probes on one device are locked out, and a log is kept for field diagnosis that excludes user-entered aliases and memos. Settings carry a schema version; a file written by a newer version is neither read nor overwritten.
- (JA) 診断とエラー処理(`docs/requirements.ja.md` §13)および設定スキーマ(§7.4)を追加。前提条件は起動時に検査し、黙って失敗せず解決方法とともに提示する。満たしている範囲の機能は使用可能とする。操作の成否は終了コードではなく `usbipd state` の再取得で確認し、タイムアウト時は成功とも失敗とも断定せず「発行したが未確認」と表示する。同一デバイスへの同時プローブは排他し、現場診断のためのログを残す(ユーザーが入力した Alias / Memo は出力しない)。設定はスキーマ版を持ち、新しい版で書かれたファイルは読まず上書きもしない。
- (EN) Add the identification policy (`docs/identification-policy.ja.md`). Probing restarts or halts the target, so it is confined to an explicit user action or an optional grace period right after a device is connected, and is forbidden during polling, list refreshes, startup scans and auto-attach decisions. Devices with a USB serial number are resolved from cache and never probed.
- (JA) 識別ポリシー(`docs/identification-policy.ja.md`)を追加。プローブは対象を再起動または停止させるため、ユーザーの明示的な操作か、接続直後の猶予時間(オプション)に限定し、定期ポーリング・一覧更新・起動時スキャン・自動 Attach 判定では禁止。USB シリアルを持つデバイスはキャッシュから復元し、プローブしない。

Records the decision to ship an NSIS per-user installer and a portable ZIP with no self-update mechanism, and to trigger releases manually from the Actions page with an explicit bump level.
- (JA) 言語・フレームワーク・配布方式の評価(`docs/platform-evaluation.ja.md`)を追加。WCH-Link プローブを既存の `ch32rv` crate に、ESP32 プローブを `espflash` に依存させ、プローブ実装の新規作成も二重保守も発生させないため Rust + Tauri 2 を選定。配布は NSIS の per-user インストーラとポータブル ZIP の 2 種のみとし自動更新機構は持たないこと、リリースは Actions 画面から bump レベルを指定して手動起動することを決定。
